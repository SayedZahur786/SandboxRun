SANDBOXRUN / PREVIEW POLICY

Privacy

Updated 19 November 2026

This notice describes the SandboxRun preview. The service executes source code in isolated WebAssembly guests and returns the result to the requesting client.

Execution data

Your source code, standard input, execution limits, and API key are sent to the API over the connection used to access the service. The application processes source and input to execute your request; it does not intentionally store execution histories or log source, input, output, or API keys. Execution receipts are returned to you.

The workbench keeps the API key in the current page’s memory. It does not write the key or your source to browser storage. Reloading or closing the page clears this application state. Avoid submitting secrets or sensitive personal information.

Usage analytics

The workbench sends two types of events: page views and run-button clicks. These events contain the event name, not your source, input, output, or API key. Service analytics may record aggregate execution status, language, duration, and request counts. There is no session replay, advertising identifier, or application tracking cookie.

Preview analytics use operational logs or process memory rather than a durable analytics database. Counts may reset and are not a complete audit history.

Hosting and operational logs

Hosting infrastructure processes requests and may retain operational data such as IP addresses, request paths, timestamps, response codes, and errors under the provider’s configuration and policies. The application’s no-history design does not mean that hosting infrastructure keeps no logs. The preview does not promise a fixed provider-log deletion period.

Your choices

You can inspect the client code and run the project locally instead of sending execution requests to the hosted preview. Do not place sensitive data in source snippets, input, URLs, or public issue reports. This preview has no user-profile or saved-run database to export.
