SANDBOXRUN / PREVIEW POLICY

Security model

Updated 19 November 2026

SandboxRun constrains execution capabilities and resources. It is an experimental preview, not an externally certified security boundary. Passing adversarial tests is evidence about tested behavior, not proof that all escapes are impossible.

The boundary

Python and JavaScript source executes inside fixed WebAssembly interpreters hosted by Rust and Wasmtime. Each request gets a fresh guest instance. The guest is not given host filesystem directories, network access, or inherited host environment variables. Source is not executed by a native host Python or Node.js process.

Python may read its interpreter’s bundled virtual standard-library files. This is distinct from access to host directories. JavaScript does not provide Node.js compatibility or arbitrary package installation.

Limits and their meaning

  • Fuel: a Wasm computational instruction budget, not CPU milliseconds.
  • Guest memory: a ceiling on guest linear memory, not total server-process memory.
  • Wall deadline: interruption of guest execution after its configured time budget. Network latency and runtime initialization are separate.
  • Output: a byte ceiling for each captured output stream.

Request sizes, concurrency, authentication, and deployment constraints add further controls. Inspect live capabilities for current runtime identities and accepted budgets. Requested limits cannot increase the service’s configured maximums.

Trusted components and remaining risks

The boundary depends on Wasmtime, interpreter artifacts, the Rust host implementation, the operating system, and hosting infrastructure. Bugs in these components, platform resource exhaustion, and side channels remain relevant risks. The preview does not promise protection against every runtime vulnerability.

Runtime compatibility is deliberately limited. There are no pip or npm installs, persistent guest sessions, or arbitrary user-provided Wasm modules. Review the repository’s runtime manifest for pinned artifact versions, hashes, and known compatibility gaps.

Output is still untrusted

A guest can print misleading instructions, HTML, terminal control sequences, or prompt injection text. The workbench displays output as text. Your integration should treat outputs as data, escape them for its display context, and avoid granting them authority over later agent actions.

Verification and reporting

Review the repository’s test results, benchmark methodology, launch checklist, and independent implementation review before deciding whether this preview fits your use case. Independent implementation review is not an external security audit.

For this project, use GitHub private vulnerability reporting when available. Use GitHub issues for non-sensitive support. If private reporting is unavailable, do not disclose exploit details publicly.

Do not publish live API keys, private data, or an actionable exploit against a hosted deployment in public issues. When using a self-hosted deployment, report security concerns directly to that deployment’s operator and stop testing if service availability is affected.
